# DS1 Companion

Нативное приложение-компаньон для **Dark Souls: Remastered** (PC, Steam) на C# / .NET 8 / WPF (MVVM).
Рассчитано на второй вертикальный монитор (1080×1920, ширина окна адаптируется в диапазоне 600–1080 px).
Во время боя ничего не отвлекает, а каждый поднятый предмет объясняет новичку простым языком:
что это, насколько редкое, зачем нужно и можно ли продать.

## Возможности

- **Спокойный экран.** Строка статуса (`DSR` / `Ожидание игры` / `Демо`, таймер сессии), текущая локация (RU/EN),
  смерти за сессию и всего, полоса «души на руках / нужно на уровень», маячки *кровавого пятна* и *прочности оружия
  ниже 30%*, текущее оружие с подсказкой по скейлингу и следующему шагу заточки, советы мыльного камня по зоне,
  4 последние находки и шторки «Персонаж и статы» (soft caps, коллекция редкого лута) и «Статистика по боссам».
- **Карточка подбора на 10 секунд.** Фон приглушается, по центру — карточка с филигранью и свечением цвета редкости,
  крупная иконка, лента редкости и категории, причина редкости, аннотация, тег (`НЕ ВЫБРАСЫВАТЬ`, `ПОЛЕЗНО В БОЮ`,
  `МОЖНО ПРОДАТЬ ФРАМПТУ`) и полоска обратного отсчёта. Наведение мыши ставит таймер на паузу. Несколько находок
  подряд встают в очередь. `Esc` закрывает карточку.
- **5 уровней редкости** — Common `#9CA3AF`, Uncommon `#22C55E`, Rare `#3B82F6`, VeryRare `#A855F7`,
  Legendary `#F59E0B` (усиленное пульсирующее золотое свечение).
- **Мягкие звуки** генерируются в коде (без внешних файлов): звон для очень редких, глубокий аккорд для
  легендарных, мягкий сигнал при низкой прочности. Громкость и Mute — в шапке окна.
- **Read-only чтение памяти** `DarkSoulsRemastered.exe` (x64): AOB-сканирование + цепочки указателей из
  `Data/offsets.json`. Никакой записи в память игры.
- **Демо-режим** с панелью тестирования: подбор предметов любой редкости (включая легендарный
  *Балдерский прямой меч*), смерть с кровавым пятном, износ оружия, смена локации, бой с боссом.
- **Окно:** своя тёмная шапка, «Поверх всех окон», запоминание монитора, позиции и размера. При первом запуске
  окно само встаёт на вертикальный (портретный) монитор, если он есть.
- **Профили персонажей** в `%AppData%/DS1Companion/`: попытки и время на боссах, коллекция редкого лута, история сессий.

## Сборка и запуск

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) и Windows 10/11.

```powershell
dotnet build
dotnet test
dotnet run --project src/DS1Companion.UI
```

Самодостаточная сборка в одну папку:

```powershell
dotnet publish src/DS1Companion.UI -c Release -r win-x64 --self-contained false -o publish
```

Рядом с `DS1Companion.exe` должны лежать папки `Data/` и `Assets/Icons/` (копируются автоматически).
Права администратора не нужны. Если DSR запущен от администратора, компаньон тоже придётся запустить от администратора,
иначе Windows не даст открыть процесс даже на чтение.

> Решение собирается и тестируется и на Linux (CI): в `Directory.Build.props` включён `EnableWindowsTargeting`,
> а тесты покрывают кроссплатформенный `DS1Companion.Core`. Для сборки WPF на Linux нужен официальный SDK от
> Microsoft — в source-built SDK из репозиториев дистрибутивов нет `Microsoft.NET.Sdk.WindowsDesktop`.

## Как пользоваться

1. Запустите компаньон и перетащите окно на второй монитор (или он встанет туда сам).
2. Запустите Dark Souls: Remastered. Когда игра найдена, точка у костра становится зелёной, статус — `DSR`.
3. Нет игры под рукой — нажмите **«Демо-режим»** в шапке и пользуйтесь панелью внизу.
4. «Персонаж и статы» → внизу настройка «Показывать большую карточку для редкости от…». Ключевые предметы
   показываются всегда, остальное сразу уходит в «Недавние находки».

## Иконки предметов

Оригинальные иконки Dark Souls принадлежат FromSoftware / Bandai Namco и **не входят** в репозиторий.
Порядок поиска иконки для предмета:

1. `Assets/Icons/{icon_key}.png`, затем `Assets/Icons/{id}.png` (поля из `Data/items_ds1.json`);
2. то же в кэше `%AppData%/DS1Companion/IconCache/`;
3. если у предмета указан `icon_url`, PNG скачивается в фоне (до 2 МБ, проверяется сигнатура PNG) и появляется
   без перезапуска;
4. иначе рисуется векторная иконка категории (меч, щит, ключ, титанит, фляга, кольцо, свиток, душа…).

Как добавить свои иконки:

```bash
# 1. Распакуйте иконки из своей копии игры. Текстуры меню лежат в архивах *.tpf.dcx в папке игры (menu/);
#    распаковать их можно инструментами сообщества (например, WitchyBND / Yabber) — получатся .dds.
# 2. Разложите их по именам предметов (Pillow нужен только для конвертации .dds → .png):
pip install pillow
python Scripts/fetch_icons.py --from-dir D:/dsr_unpacked/icons --map my_icon_map.csv
# my_icon_map.csv — строки вида: balder_side_sword,MENU_Icon_00123.dds

# Или скачать по шаблону URL из выбранного вами источника:
python Scripts/fetch_icons.py --url-template "https://example.org/icons/{name_en_slug}.png"

# Или прописать icon_url — приложение будет докачивать иконки само:
python Scripts/fetch_icons.py --write-icon-urls "https://example.org/icons/{name_en_slug}.png"

# Что ещё без иконки:
python Scripts/fetch_icons.py --list-missing
```

Подойдёт любой квадратный PNG; оптимально 128×128 с прозрачным фоном.

## Данные

| Файл | Содержимое |
|---|---|
| `Data/items_ds1.json` | 136 предметов: ключи, угли, титаниты, расходники, кольца, оружие, заклинания, души, мусор |
| `Data/weapons_upgrade_ds1.json` | пути заточки (обычный, уникальный, босс, драконий) и скейлинг 27 видов оружия |
| `Data/locations_ds1.json` | 28 локаций с советами, привязка к карте `mAA_BB` |
| `Data/bosses_ds1.json` | 27 боссов с локациями |
| `Data/offsets.json` | карта памяти DSR для read-only чтения |

Поля предмета: `id`, `name_ru`, `name_en`, `category` (`Equipment`, `Upgrade`, `KeyItem`, `Consumable`, `Spell`, `Junk`),
`rarity`, `rarity_reason`, `summary_ru`, `keep_status` (`DoNotDiscard`, `UsefulInCombat`, `SellToFrampt`, `Situational`),
`icon_key`, а также необязательные `icon_url`, `glyph`, `game_kind` (`Weapon`/`Armor`/`Ring`/`Goods`) и `game_id`
(ID из EquipParam игры; для оружия — базовый ID без заточки). Предмет без `game_id` виден только в демо-режиме.

Если в инвентаре появился предмет, которого нет в базе, компаньон покажет карточку «Неизвестный предмет #ID» —
этот ID можно добавить в `items_ds1.json`.

## Статус точности (важно)

- **`Data/offsets.json` не проверен на живой игре** (`verified: false`). AOB-шаблоны и смещения собраны по открытым
  данным сообщества для DSR 1.03.x и могут не совпасть с вашей версией. Компаньон защищён от этого: неправдоподобные
  значения (уровень > 713, статы вне 1–99 и т. п.) отбрасываются, поле показывается как «—», а приложение не падает.
  Журнал поиска баз пишется в `%AppData%/DS1Companion/logs/memory.log`. Исправленные смещения подхватываются без пересборки.
- **`game_id` предметов и буквы скейлинга** — ориентировочные. Сверьте с вики/параметрами игры для полного соответствия.
- Описания предметов и советы написаны для новичков и намеренно упрощены.

## Архитектура

```
DS1Companion.sln
├─ Data/                      база знаний и offsets.json (копируются рядом с exe)
├─ Scripts/fetch_icons.py     подготовка иконок
├─ src/DS1Companion.Core      net8.0, без WPF: модели, логика, чтение памяти, ViewModel'и
│  ├─ Models/        ItemInfo, GameSnapshot, перечисления, подписи и цвета
│  ├─ Data/          KnowledgeBase (загрузка и поиск по JSON)
│  ├─ Game/          IGameStateReader, MockGameStateReader, GameSessionTracker (diff → события)
│  ├─ Memory/        DsrMemoryReader, WindowsProcessMemory (read-only WinAPI), AobScanner, PointerChain, OffsetsConfig
│  ├─ Logic/         SoulsCalculator, PopupCountdown, InventoryDiff, RarityFilter, SoftCapAdvisor, UpgradeAdvisor
│  ├─ Services/      IIconProvider + кэширующий провайдер, ISoundService, WavSynth, IClock
│  ├─ Persistence/   AppPaths, настройки, профили персонажей
│  └─ Presentation/  MainViewModel, ItemCardViewModel, DemoPanelViewModel и др. (CommunityToolkit.Mvvm)
├─ src/DS1Companion.UI        net8.0-windows, WPF: окна, тема, контролы, звук, опрос игры, позиция окна
└─ tests/DS1Companion.Tests   xUnit, 114 тестов
```

Опрос игры идёт в фоновом потоке (`GamePollingService`, по умолчанию раз в 250 мс), снимок обрабатывается в UI-потоке
трекером, который превращает разницу снимков в события (подбор, смерть, пятно, локация, прочность, босс).
Время для карточки подаётся из UI-таймера через `MainViewModel.Tick`, поэтому обратный отсчёт и пауза при наведении
детерминированы и покрыты тестами.

Тесты включают статическую проверку XAML: каждый `{Binding}` сверяется со свойствами ViewModel через рефлексию,
каждый `{StaticResource}` — с объявленными ключами. Это ловит опечатки в биндингах без запуска WPF.
