# Souls Companion

Нативное приложение-компаньон для игр FromSoftware на C# / .NET 8 / WPF (MVVM).
Рассчитано на второй вертикальный монитор (1080×1920, ширина окна адаптируется в диапазоне 600–1080 px).
Во время боя ничего не отвлекает, а каждый поднятый предмет объясняет новичку простым языком:
что это, насколько оно редкое, зачем нужно и стоит ли его хранить.

| Игра | Статус |
|---|---|
| Dark Souls: Remastered | данные готовы (136 предметов, 28 локаций, 27 боссов), чтение памяти не проверено на живой игре |
| Dark Souls II: Scholar of the First Sin | данные готовы (124 предмета, 29 локаций, 28 боссов), Опустошение и Чучело человека, чтение памяти не проверено |
| Dark Souls III | в планах |
| Sekiro: Shadows Die Twice | в планах (ядро уже поддерживает игры без уровней и без кровавого пятна) |
| Elden Ring | в планах (формула стоимости уровня уже реализована) |

Компаньон сам определяет, какая игра запущена, и переключает данные, подписи и механики.
В демо-режиме игра выбирается в переключателе в шапке.

## Возможности

- **Спокойный экран.** Строка статуса (игра / `Ожидание игры` / `Демо`, таймер сессии), текущая локация (RU/EN),
  смерти за сессию и всего, полоса «души на руках / нужно на уровень» (руны, сэн — по игре), маячки *кровавого пятна*,
  *Опустошения* (DS2) и *прочности оружия ниже 30%*, текущее оружие с подсказкой по скейлингу и следующему шагу
  заточки, советы мыльного камня по зоне, 4 последние находки и шторки «Персонаж и статы» (пороги характеристик
  каждой игры, коллекция редкого лута) и «Статистика по боссам».
- **Карточка подбора на 10 секунд.** Фон приглушается, по центру — карточка с филигранью и свечением цвета редкости,
  крупная иконка, лента редкости и категории, причина редкости, аннотация, тег (`НЕ ВЫБРАСЫВАТЬ`, `ПОЛЕЗНО В БОЮ`,
  `МОЖНО ПРОДАТЬ ФРАМПТУ` / `МОЖНО НЕ ХРАНИТЬ`) и полоска обратного отсчёта. Наведение мыши ставит таймер на паузу.
  Несколько находок подряд встают в очередь. `Esc` закрывает карточку.
- **5 уровней редкости** — Common `#9CA3AF`, Uncommon `#22C55E`, Rare `#3B82F6`, VeryRare `#A855F7`,
  Legendary `#F59E0B` (усиленное пульсирующее золотое свечение).
- **Мягкие звуки** генерируются в коде: звон для очень редких, глубокий аккорд для легендарных, мягкий сигнал при
  низкой прочности. Громкость и Mute — в шапке окна.
- **Read-only чтение памяти** (x64): AOB-сканирование + цепочки указателей из `Data/{игра}/offsets.json`.
  Никакой записи в память игры.
- **Демо-режим** для каждой игры: подбор предметов любой редкости, смерть с кровавым пятном, Опустошение (DS2),
  износ и заточка оружия, смена локации, бой с боссом.
- **Окно:** своя тёмная шапка, «Поверх всех окон», запоминание монитора, позиции и размера. При первом запуске
  окно само встаёт на вертикальный (портретный) монитор, если он есть.
- **Профили** отдельно для каждой игры и персонажа в `%AppData%/DS1Companion/profiles/{игра}/`.

## Сборка и запуск

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) и Windows 10/11.

```powershell
dotnet build
dotnet test
dotnet run --project src/DS1Companion.UI
```

Сборка в папку:

```powershell
dotnet publish src/DS1Companion.UI -c Release -r win-x64 --self-contained false -o publish
```

Рядом с `DS1Companion.exe` должны лежать папки `Data/` и `Assets/Icons/` (копируются автоматически).
Права администратора не нужны. Если игра запущена от администратора, компаньон тоже придётся запустить
от администратора, иначе Windows не даст открыть процесс даже на чтение.

> Решение собирается и тестируется и на Linux (CI): в `Directory.Build.props` включён `EnableWindowsTargeting`,
> а тесты покрывают кроссплатформенный `DS1Companion.Core`. Для сборки WPF на Linux нужен официальный SDK от
> Microsoft — в source-built SDK из репозиториев дистрибутивов нет `Microsoft.NET.Sdk.WindowsDesktop`.

## Как пользоваться

1. Запустите компаньон и перетащите окно на второй монитор (или он встанет туда сам).
2. Запустите игру. Когда она найдена, точка у костра становится зелёной, а в статусе появляется её название.
3. Нет игры под рукой — выберите игру в шапке и нажмите **«Демо-режим»**. Внизу появится панель для симуляции.
4. «Персонаж и статы» → внизу настройка «Показывать большую карточку для редкости от…». Ключевые предметы
   показываются всегда, остальное сразу уходит в «Недавние находки».

## Иконки предметов

Оригинальные иконки игр принадлежат FromSoftware / Bandai Namco и **не входят** в репозиторий
(`Assets/Icons/**/*.png` исключены из git). Порядок поиска иконки:

1. `Assets/Icons/{игра}/{icon_key}.png`, затем `{id}.png`; потом то же в общем `Assets/Icons/`;
2. то же в кэше `%AppData%/DS1Companion/IconCache/`;
3. если у предмета указан `icon_url`, PNG скачивается в фоне и появляется без перезапуска;
4. иначе рисуется векторная иконка категории.

### Оригинальные иконки одной командой (на вашем ПК)

```powershell
pip install pillow                                   # необязательно: уменьшит картинки до 128×128
python Scripts/fetch_icons.py --game ds1 --wiki      # Dark Souls
python Scripts/fetch_icons.py --game ds2 --wiki      # Dark Souls II
dotnet build                                         # иконки окажутся рядом с exe
```

Скрипт открывает страницу каждого предмета на вики игры (Fextralife) по английскому названию и забирает оттуда
картинку предмета (~1 запрос в секунду). Если для каких-то предметов страница называется иначе, скрипт выведет их
список: задайте название вручную в CSV (`item_id,Название страницы`) и запустите
`python Scripts/fetch_icons.py --game ds2 --wiki --wiki-titles titles.csv --only <id> ...`.
Скрипт пока не запускался на живом сайте: разбор страниц проверен на тестовых примерах.

### Другие способы

```bash
# Из распакованных файлов своей копии игры (текстуры меню в архивах *.tpf.dcx; распаковка — WitchyBND / Yabber):
python Scripts/fetch_icons.py --game ds1 --from-dir D:/unpacked/icons --map my_icon_map.csv
# my_icon_map.csv — строки вида: balder_side_sword,MENU_Icon_00123.dds

# По шаблону URL или прописав icon_url (приложение будет докачивать само):
python Scripts/fetch_icons.py --game ds1 --url-template "https://example.org/icons/{name_en_slug}.png"
python Scripts/fetch_icons.py --game ds1 --write-icon-urls "https://example.org/icons/{name_en_slug}.png"

python Scripts/fetch_icons.py --game ds2 --list-missing
```

## Данные

Каждая игра — отдельная папка `Data/{игра}/`:

| Файл | Содержимое |
|---|---|
| `game.json` | описание игры: процесс, валюта, механики (уровни, кровавое пятно, Опустошение, прочность), характеристики и их пороги, стартовое состояние демо |
| `items.json` | предметы |
| `weapons_upgrade.json` | пути заточки и скейлинг оружия |
| `locations.json` | локации с советами |
| `bosses.json` | боссы |
| `offsets.json` | карта памяти для read-only чтения |

Поля предмета: `id`, `name_ru`, `name_en`, `category` (`Equipment`, `Upgrade`, `KeyItem`, `Consumable`, `Spell`, `Junk`),
`rarity`, `rarity_reason`, `summary_ru`, `keep_status` (`DoNotDiscard`, `UsefulInCombat`, `SellToFrampt` — «можно избавиться»,
подпись зависит от игры, `Situational`), `icon_key`, а также необязательные `icon_url`, `glyph`, `game_kind`
(`Weapon`/`Armor`/`Ring`/`Goods`) и `game_id` (ID из параметров игры; для оружия — базовый ID без заточки).

Если в инвентаре появился предмет, которого нет в базе, компаньон покажет карточку «Неизвестный предмет #ID» —
этот ID можно добавить в `items.json`.

## Статус точности (важно)

- **`offsets.json` не проверены на живых играх** (`verified: false`). AOB-шаблоны и смещения собраны по открытым
  данным сообщества и могут не совпасть с вашей версией. Неправдоподобные значения отбрасываются, поле показывается
  как «—», приложение не падает. Журнал — `%AppData%/DS1Companion/logs/memory.log`. Исправленные смещения подхватываются
  без пересборки. Для DS2 чтение инвентаря пока не описано: подбор предметов в DS2 заработает после калибровки на ПК.
- **`game_id` предметов и буквы скейлинга** — ориентировочные. В DS2 `game_id` пока не заполнены.
- **Русские названия** DS2 даны по смыслу и могут отличаться от официальной локализации.
- Описания предметов и советы написаны для новичков и намеренно упрощены.

## Архитектура

```
DS1Companion.sln
├─ Data/{ds1,ds2}/            база знаний и offsets.json по играм (копируются рядом с exe)
├─ Scripts/fetch_icons.py     подготовка иконок
├─ src/DS1Companion.Core      net8.0, без WPF: модели, логика, чтение памяти, ViewModel'и
│  ├─ Models/        GameDefinition, ItemInfo, GameSnapshot, перечисления, подписи и цвета
│  ├─ Data/          GameCatalog (все игры), KnowledgeBase (одна игра)
│  ├─ Game/          IGameStateReader, MultiGameReader (автоопределение), MockGameStateReader, GameSessionTracker
│  ├─ Memory/        GameMemoryReader, WindowsProcessMemory (read-only WinAPI), AobScanner, PointerChain, OffsetsConfig
│  ├─ Logic/         LevelCurve, SoulsCalculator, PopupCountdown, InventoryDiff, RarityFilter, SoftCapAdvisor, UpgradeAdvisor
│  ├─ Services/      IIconProvider + кэширующий провайдер, ISoundService, WavSynth, IClock
│  ├─ Persistence/   AppPaths, настройки, профили персонажей
│  └─ Presentation/  MainViewModel, ItemCardViewModel, DemoPanelViewModel и др. (CommunityToolkit.Mvvm)
├─ src/DS1Companion.UI        net8.0-windows, WPF: окна, тема, контролы, звук, опрос игры, позиция окна
└─ tests/DS1Companion.Tests   xUnit, 134 теста
```

Имена проектов остались от первой версии (`DS1Companion.*`); приложение называется Souls Companion.

Опрос игры идёт в фоновом потоке (`GamePollingService`, по умолчанию раз в 250 мс). `MultiGameReader` по очереди
ищет процессы всех игр; снимок с другой игрой переключает базу знаний, трекер и профиль. Трекер превращает разницу
снимков в события (подбор, смерть, пятно, локация, прочность, босс). Время для карточки подаётся из UI-таймера через
`MainViewModel.Tick`, поэтому обратный отсчёт и пауза при наведении детерминированы и покрыты тестами.

Тесты включают статическую проверку XAML: каждый `{Binding}` сверяется со свойствами ViewModel через рефлексию,
каждый `{StaticResource}` — с объявленными ключами. Данные всех игр проверяются одним набором тестов.

## Как добавить игру

1. Создайте `Data/{игра}/game.json` (образец — `Data/ds2/game.json`): ключ из `GameKey`, имена процессов, валюта,
   `level_curve` (`ds1`, `souls3` для DS3/Elden Ring, `memory`, `none`), флаги механик, характеристики, демо.
2. Добавьте `items.json`, `locations.json`, `bosses.json`, при необходимости `weapons_upgrade.json` и `offsets.json`.
3. `dotnet test` — общие тесты данных сразу проверят новую игру.
